# elementskin-union-svc 使用与测试手册

## 1. 编译

```bash
cd /home/ubuntu/dev/elementskin-union-svc
go build ./cmd/union-svc
```

生成 `./union-svc` 二进制文件，内嵌所有静态资源（index.html、admin.html、admin.js），无外部文件依赖。

Docker 构建：

```bash
docker build -t elementskin-union-svc .
```

## 2. 配置

```bash
cp config.yaml.example config.yaml
```

编辑 `config.yaml`：

```yaml
server:
  addr: ""          # 监听地址，空=0.0.0.0
  port: 8267
  root_path: ""     # 子路径前缀，如 "/union-svc"。独立域名部署留空

elementskin:
  base_url: "https://skin.example.com/skinapi"
  site_url: "https://skin.example.com"
  oauth:
    client_id: "用户授权应用ID"
    client_secret: "用户授权应用密钥"
    redirect_uri: "https://union.example.com/oauth/callback"
  service_account:
    client_id: "服务账号应用ID"
    client_secret: "服务账号应用密钥"
    scope: "profile.read.any"

union:
  hub_url: "https://hub.example.com/api/union"
  member_key: "Hub分配的成员密钥"
  admin_api_key: ""        # openssl rand -hex 32 生成
  webhook_secret: ""       # openssl rand -hex 32 生成
  cors_allow_origin: ""
  enable_oauth2: true

storage:
  path: "./union-svc.db"
```

环境变量覆盖：所有字段可用 `UNION_` 前缀（如 `UNION_UNION_HUB_URL`）。

生成密钥：

```bash
openssl rand -hex 32  # admin_api_key
openssl rand -hex 32  # webhook_secret
```

OAuth2 签名密钥首次启动时自动生成，无需手动创建。

## 3. 启动

```bash
./union-svc --config config.yaml
```

Docker：

```bash
docker compose up -d
```

验证启动：

```bash
curl http://127.0.0.1:8267/health
# 期望: {"status":"ok"}
```

## 4. Nginx 反向代理

### 独立域名部署

```nginx
server {
    listen 443 ssl;
    server_name union.example.com;

    location / {
        proxy_pass http://127.0.0.1:8267;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

`config.yaml` 中 `root_path` 留空。Hub 成员地址配 `https://union.example.com`。

### 子路径部署

Hub 回调路径硬编码为 `/api/union/*`，而 svc 自身路由受 `root_path` 影响。通过 nginx 路径改写使两者兼容：

```nginx
# Hub 回调 — 路径改写：/api/union/* → /union-svc/api/union/*
location /api/union/ {
    proxy_pass http://127.0.0.1:8267/union-svc/api/union/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

# 用户侧 svc 路由（UI、OAuth、用户 API、管理 API 等）
location /union-svc/ {
    proxy_pass http://127.0.0.1:8267;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

`config.yaml` 中 `root_path: "/union-svc"`。Hub 成员地址配 `https://example.com`（Hub 自行追加 `/api/union/member/...`），OAuth `redirect_uri` 配 `https://example.com/union-svc/oauth/callback`。

## 5. Element-Skin 侧配置

在 Element-Skin 管理后台创建两个 OAuth 应用：

### 用户授权应用

| 配置项 | 值 |
|---|---|
| 名称 | union-svc |
| 类型 | Confidential |
| Grant Type | Authorization Code |
| Redirect URI | `https://union.example.com/oauth/callback`（或子路径） |
| Scope | `account.read.self profile.read.owned` |

### 服务账号应用

| 配置项 | 值 |
|---|---|
| 名称 | union-svc-service |
| 类型 | Confidential |
| Grant Type | Client Credentials |
| Scope | `profile.read.any` |

两个应用的 `client_id` 和 `client_secret` 填入 union-svc 的 `config.yaml`。

## 6. 用户侧使用

### 浏览器操作流程

1. 访问 `https://union.example.com/`（或 `https://example.com/union-svc/`）
2. 点击「授权」→ 跳转到 Element-Skin 登录 → 授权 union-svc → 回调返回
3. 页面显示「授权完成」，安全等级自动加载
4. 输入 Union 用户名 → 点击「查询」→ 显示角色列表
5. 每个角色旁有「绑定」/「解绑」按钮
6. 点击「绑定」→ 角色绑定到 Union 网络（后端验证 UUID 归属）
7. 点击「解绑」→ 解除绑定（同样验证归属）

### API 直接调用

需要 Element-Skin 用户 access token（通过 OAuth 授权码流程获取）：

```bash
# 查询角色
curl -H "Authorization: Bearer {access_token}" \
  "https://union.example.com/api/profiles?username=Steve"

# 绑定角色
curl -X POST -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{"uuid":"abc123"}' \
  https://union.example.com/api/union/profile/bind

# 解绑角色
curl -X POST -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{"uuid":"abc123"}' \
  https://union.example.com/api/union/profile/unbind

# 安全等级
curl -H "Authorization: Bearer {access_token}" \
  https://union.example.com/api/union/security/level
```

## 7. 管理员侧使用

### 管理面板

1. 访问 `https://union.example.com/admin`
2. 输入 admin_api_key → 点击「登录」→ 存入 localStorage
3. 状态概览自动加载（member_key 配置状态、Hub 连通性、版本号、OAuth2 状态）
4. 功能区操作：
   - 「全站同步」→ 推送全站角色到 Hub
   - 「拉取服务器列表」/「拉取私钥」/「诊断」→ 手动 Hub 操作
   - 「轮换密钥」→ 勾选 confirm → 轮换 OAuth2 签名密钥
   - 「查询黑名单」→ 查看/删除黑名单条目

### API 直接调用

```bash
KEY="admin_api_key值"
BASE="https://union.example.com"

# 状态
curl -H "Authorization: Bearer $KEY" $BASE/api/union/admin/status

# 全站同步
curl -X POST -H "Authorization: Bearer $KEY" $BASE/api/union/admin/sync

# 拉取服务器列表
curl -X POST -H "Authorization: Bearer $KEY" $BASE/api/union/admin/update-list

# 拉取私钥
curl -X POST -H "Authorization: Bearer $KEY" $BASE/api/union/admin/update-key

# 诊断
curl -X POST -H "Authorization: Bearer $KEY" $BASE/api/union/admin/diagnose

# 密钥指纹
curl -H "Authorization: Bearer $KEY" $BASE/api/union/admin/keypair-fingerprint

# 轮换密钥
curl -X POST -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"confirm":true}' \
  $BASE/api/union/admin/regenerate-keypair
```

## 10. 验证清单

部署后逐项验证：

```bash
BASE="https://union.example.com"  # 或 https://example.com/union-svc

# 1. 健康检查
curl $BASE/health
# 期望: {"status":"ok"}

# 2. 用户页面可访问
curl -s $BASE/ | grep "Union 角色查询"
# 期望: 有匹配

# 3. 管理面板可访问（含 CSP header）
curl -I $BASE/admin | grep Content-Security-Policy
# 期望: 有 CSP header

# 4. admin.js 可访问
curl -s $BASE/admin.js | head -1
# 期望: (function() {

# 5. 未认证访问 admin API → 401
curl -s -o /dev/null -w "%{http_code}" -X POST $BASE/api/union/admin/sync
# 期望: 401

# 6. 错误 key 访问 admin API → 401
curl -s -o /dev/null -w "%{http_code}" -H "Authorization: Bearer wrong" $BASE/api/union/admin/status
# 期望: 401

# 7. 正确 key 访问 status → 200
curl -s -H "Authorization: Bearer $ADMIN_KEY" $BASE/api/union/admin/status
# 期望: {"member_key_configured":...,"hub_reachable":...}

# 8. 速率限制：连续 11 次 admin 请求 → 第 11 次 429
for i in $(seq 1 11); do
  curl -s -o /dev/null -w "$i: %{http_code}\n" -H "Authorization: Bearer $ADMIN_KEY" $BASE/api/union/admin/status
done
# 期望: 1-10 为 200, 11 为 429

# 9. 未认证访问用户 API → 401
curl -s -o /dev/null -w "%{http_code}" $BASE/api/profiles?username=test
# 期望: 401

# 10. OAuth 授权页可跳转
curl -s -o /dev/null -w "%{redirect_url}" $BASE/oauth/authorize
# 期望: 跳转到 element-skin /oauth/authorize
